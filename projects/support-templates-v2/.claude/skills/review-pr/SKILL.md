## Code Review

Виконай структурований code review поточних змін:

### 1. Збери контекст

- Запусти `git diff HEAD~1 --stat` — список змінених файлів
- Запусти `git diff HEAD~1` — детальний diff

### 2. Автоматичні перевірки

- `npm run typecheck` — TypeScript помилки
- `npm run lint` — ESLint порушення
- Якщо є помилки — вкажи файл і рядок

### 3. Ручний аналіз

Пройдись по кожному зміненому файлу і перевір:

**Стиль коду (з code-style.md):**
- Plain JavaScript — без TypeScript-анотацій
- Тільки functional components, без class components
- Немає зайвих абстракцій — три схожі рядки краще передчасної абстракції
- Коментарі тільки якщо WHY не очевидний
- Нові шаблони через factory-функції де є відповідний генератор
- `id` шаблонів — kebab-case, унікальний в межах усього масиву

**Якість змін:**
- Логіка відповідає меті PR
- Немає зайвого коду, debug-логів, закоментованого коду
- Немає регресій в наявному функціоналі

### 4. Звіт

Виведи підсумок у форматі:

```
## Code Review

**Автоматичні перевірки:** ✅ пройдено / ❌ помилки

**Файли змінено:** N

### Зауваження
- [файл:рядок] опис проблеми (critical / minor)

### Підсумок
Короткий висновок: чи готово до мержу, що потребує виправлення.
```

Якщо зауважень немає — скажи "Готово до мержу".
