# PRD: Система фільтрів для бібліотеки шаблонів

**Статус:** Draft  
**Дата:** 2026-05-23  
**Автор:** Denys  

---

## 1. Проблема

Поточна система фільтрації має три обмеження:

| Проблема | Деталь |
|---|---|
| Категорії приховані | `category`-фільтр існує в коді, але недоступний у UI |
| Теги не організовані | 50+ тегів у пласкому списку, перші 15 по частоті — без логіки угруповання |
| Один тег за раз | Неможливо знайти шаблони одночасно для `billing` + `escalation` |

**Наслідок:** агент витрачає зайвий час на пошук релевантного шаблону або використовує текстовий пошук там, де структурований фільтр було б швидше.

---

## 2. Цілі

- Агент може звузити 304 шаблони до потрібної підмножини за ≤ 3 кліки.
- Категорія видима як перший рівень навігації (9 категорій).
- Можна обрати кілька тегів одночасно з перемикачем AND/OR.
- Активні фільтри завжди помітні й легко скидаються.

**Не в цілях:** зміна самих даних шаблонів, редагування/додавання тегів, мобільна адаптація (app is desktop-only).

## 3. User stories

```
Як агент підтримки, я хочу відфільтрувати шаблони спочатку за категорією "billing",
а потім звузити до тегів "escalation" + "empathy",
щоб швидко знайти саме escalation-шаблон для білінгу.

Як агент підтримки, я хочу бачити кількість шаблонів поруч із кожним тегом/категорією,
щоб розуміти, чи варто взагалі обирати цей фільтр.

Як агент підтримки, я хочу скинути всі фільтри одним кліком,
щоб повернутись до повного списку.
```

## 4. Функціональні вимоги

### 4.1 Категорії — первинний фільтр

- Категорії відображаються як горизонтальний ряд кнопок-chips над списком тегів усередині фільтр-панелі.
- Варіанти: **All** (за замовчуванням) + 9 категорій: `core`, `billing`, `esp`, `plugin`, `editor`, `new-editor`, `troubleshooting`, `setup`, `kb`.
- Single-select: вибір нової категорії знімає попередню.
- Поруч із кожною категорією — лічильник шаблонів `(N)`, що оновлюється з урахуванням поточного текстового пошуку.
- Вибір категорії фільтрує список тегів нижче: показуються лише теги, які є в шаблонах цієї категорії.

**Відображувані назви категорій — англійською, фіксований порядок:**

| # | key | Назва в UI |
|---|---|---|
| 0 | all | All |
| 1 | core | Core |
| 2 | billing | Billing |
| 3 | esp | ESP |
| 4 | plugin | Plugin |
| 5 | editor | Editor |
| 6 | new-editor | New Editor |
| 7 | troubleshooting | Troubleshooting |
| 8 | setup | Setup |
| 9 | kb | Knowledge Base |

### 4.2 Теги — вторинний фільтр

- Теги відображаються як checkbox-chips у фільтр-панелі після категорій.
- **Multi-select**: можна обрати кілька тегів одночасно.
- Поруч із кожним тегом — лічильник `(N)` — кількість шаблонів за поточними фільтрами (категорія + пошук), що мають цей тег.
- Теги з `(0)` шаблонів — **не відображаються**.
- Сортування: спочатку обрані, потім решта за частотою (спадання).

### 4.3 Логіка AND / OR

- У фільтр-панелі є перемикач `AND / OR` (toggle), активний лише якщо обрано ≥ 2 теги.
- **AND** (за замовчуванням): шаблон показується, якщо містить **усі** обрані теги.
- **OR**: шаблон показується, якщо містить **хоча б один** обраний тег.
- При скиданні тегів перемикач залишається в тому самому стані.

### 4.4 Фільтр-панель (drawer)

- Над списком шаблонів є кнопка **"Фільтри"**.
  - Коли фільтри не активні: звичайна кнопка.
  - Коли є активні фільтри: на кнопці бейдж із кількістю активних фільтрів (категорія не рахується, якщо "Всі").
- Кнопка розкриває/закриває panel expander (не modal drawer, а вбудований блок у sidebar).
- Панель містить: категорії → теги → AND/OR toggle → кнопка "Скинути все".
- **"Скинути все"** видаляє всі обрані теги, повертає категорію до "Всі", toggle до AND. Рядок пошуку **не** скидає.

### 4.5 Active filters summary

- Під кнопкою "Фільтри" (поза панеллю) відображається рядок активних фільтрів у вигляді pill-chips із `×` для кожного.
- Кожен chip можна видалити індивідуально.
- Якщо фільтрів немає — рядок прихований.

## 5. Зміни стану (App.jsx / useTemplatesFilters)

### Поточний стан → новий стан

| Поле | Було | Стане |
|---|---|---|
| `activeTag` | `string \| null` | видалити |
| `activeTags` | немає | `string[]` (замість `activeTag`) |
| `tagLogic` | немає | `'AND' \| 'OR'` (default `'AND'`) |
| `category` | `string \| null` | залишити, але тепер прив'язати до UI |
| `filtersOpen` | немає | `boolean` (default `false`) |
| `showAllTags` | `boolean` | видалити (теги тепер у панелі, всі видимі) |

### Логіка фільтрації (useTemplatesFilters.js)

```
matchesCategory && matchesSearch && matchesTags

де matchesTags:
  if activeTags.length === 0 → true
  if tagLogic === 'AND' → activeTags.every(tag => template.tags.includes(tag))
  if tagLogic === 'OR'  → activeTags.some(tag  => template.tags.includes(tag))
```

## 6. Нові компоненти

| Компонент | Відповідальність |
|---|---|
| `FilterPanel.jsx` | Весь expander-блок (категорії + теги + toggle + reset) |
| `CategoryChips.jsx` | Ряд chip-кнопок категорій |
| `TagChips.jsx` | Checkbox-chips тегів (замінює поточний блок тегів у App.jsx) |
| `AndOrToggle.jsx` | Перемикач AND/OR |
| `ActiveFiltersSummary.jsx` | Рядок активних pills під кнопкою |

Поточний inline-блок тегів у `App.jsx` — видалити, логіку перенести у `FilterPanel`.

## 9. Критерії приймання

- [ ] Кнопка "Фільтри" розкриває панель з категоріями і тегами.
- [ ] Вибір категорії фільтрує список шаблонів і звужує список тегів.
- [ ] Вибір кількох тегів + AND повертає лише шаблони з усіма тегами.

- [ ] Бейдж на кнопці "Фільтри" показує кількість активних фільтрів.
- [ ] Pill-chips під кнопкою відображають активні фільтри; клік `×` видаляє конкретний.
- [ ] "Скинути все" очищає всі фільтри крім пошуку.
